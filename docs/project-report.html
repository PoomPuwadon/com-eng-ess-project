FINANCIAL FIRM — Project Report

Computer Engineering Essential · Final Project, Semester 1/2026 · Free Track

1. Problem and idea

Instead of a club problem from the Problem Bank, our team proposed a Free Track project: a multiplayer, walkable 3D web world of an absurdly luxurious mock financial firm, played as satire. It is not a game with a score or an ending. It is a living simulation that runs 24/7: AI employees trade, research and bet using real-world free data with fake money only, while real players walk through the building, chat and play.

The aim was to show how far one team can get with AI-assisted development (vibe coding) on a project that combines real-time 3D, a server-side simulation, real external APIs and several AI models, while keeping cost at or near zero.

Legal context. Stock trading and the government lottery are legal activities in Thailand, which is why the trading floor and lottery room use real market data and official draw results. The project itself is fake-money only by design: there are no deposits, purchases or payouts, and all balances are notional.

2. What the system does

  • Building: a grand lobby splitting into a staff Office Tower and a public Visitors' Tower, joined by a glass bridge, with a basement vault, working elevators and a minimap.
  • Roles: Visitor (default), CEO and Staff admins. Admins set balances, budgets and per-visitor clearances; every change is kept in an audit log.
  • Fake-money economy: one append-only double-entry ledger. All firm money lives in the vault, budget transfers are shown as cash-robot trips, and visitor wins and losses flow through the vault.
  • Trading floor: real US stock data (delayed), two rival AI trading desks, a risk officer that can only veto, and live P&L screens anyone can read.
  • Visitors' Tower: roulette and table games, a football arena with real fixtures, odds and crests, a Muay Thai ring, horse racing and a Thai lottery room using official draw results.
  • Chart Desk: a visitor uploads a chart image and the AI returns an UP/DOWN verdict with reasoning.

4. Architecture

LayerChoice and reason
ClientThree.js with Vite. Instanced low-poly meshes for seats, screens and people, and floors built as you reach them, so huge rooms stay smooth on a laptop.
ServerOne Node.js process: HTTP API plus WebSockets (ws) for presence, chat and live events. A server tick runs the firm whether or not anyone is online.
DatabaseSupabase Postgres is the database of record. At startup the server loads every table from Supabase into an in-memory SQLite working set; every row change is captured by triggers and replicated to Supabase in ordered batches every 1.5 seconds, plus a final flush on shutdown. Money writes are single transactions in the working set, and append-only triggers in both SQLite and Postgres stop the ledger being edited.
AuthServer-side sign-up, log-in and log-out against the Supabase users table; the server verifies each session token before any action. Row-level security is on for every table and the public Data API has no access, so only the server can read or write.
HostingRender free web service serves the built client and the API/WebSocket from one public URL, so it stays reachable with every team PC off. A free uptime monitor pings it to avoid idle sleep.
SecretsAPI keys live only in .env.local on the server (gitignored), never in client code. .env.example is committed.

5. AI design

Two providers run side by side: Claude (claude-haiku-5-5) and Gemini (free tier). Each agent has a preferred provider, and if a key is missing the call goes to the other one.

  • Agents propose, the server disposes. Model output is untrusted. Every money action passes a gateway that checks privileges, daily caps and maximum stake, and hard limits are enforced in code.
  • Fallback: with no key, an error, a refusal or an open cost breaker, every agent falls back to a deterministic rule book. The firm always runs for free.
  • Model League: every order, fill and lottery ticket records which model decided it, so Claude, Gemini and the rule book can be compared on P&L, calls and cost.
  • Cost control: token usage is metered against a price table. One monthly cap (default $75) with a circuit breaker slows at 70%, allows events only at 90% and stops at 100%. Background characters never make their own LLM calls.

7. Testing

Server logic (ledger invariants, settlement, gateway limits) is covered by node --test suites. The 3D client was checked by walking each floor in the browser, taking screenshots and measuring frame rate; evidence is stored in the verification/ folder. A copy-check script scans all player-visible text for banned words.

8. Limitations and next steps

  • Real two-player boxing and racing were simulated locally and not yet run with two live players.
  • Free data tiers are rate-limited, so some boards fill in over several polling cycles.
  • There is no dark-mode toggle and no per-user favourites list.
  • All data lives in Supabase, so the free Render instance can restart without losing accounts or balances. Writes in the last second or so before a crash may be lost, and the free Supabase tier has storage limits and pauses after a week of inactivity.
  • The free instance sleeps after idle time (first load can take about a minute); an uptime ping mitigates this.
